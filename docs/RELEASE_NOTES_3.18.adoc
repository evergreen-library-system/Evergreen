= Cataloging =


== New Added Content Provider ==

Loral for Libraries is available as a new Added Content
Provider. Loral can provide the following enhancements for your
catalog:

 * Book Covers
 * Author Biographies
 * Summaries
 * Reviews

=== Activating Loral for Libraries ===

Loral for Libraries is a subscription service.

To activate the Loral for Libraries added content provider, first
comment out the default OpenLibrary module in
_/openils/conf/opensrf.xml_ by adding _<!--_ and _-->_ to the
beginning and end of the line, respectively:

----
<!-- <module>OpenILS::WWW::AddedContent::OpenLibrary</module> -->
----

Uncomment the _<module>_ and _<base_url>_ elements for Loral by
removing the _<!--_ and _-->_ from the lines:

----
<module>OpenILS::WWW::AddedContent::Loral</module>
<base_url>https://api.loralforlibraries.com</base_url>
----

Replace _MY_USER_ID_ and _MY_PASSWORD_ in the _<userid>_ and
_<password>_ child elements of the _<Loral>_ element with your Loral
ID and password:

----
<Loral>
    <userid>MY_USER_ID</userid>
    <password>MY_PASSWORD</password>
</Loral>
----

Finally, you will need to restart Evergreen and Apache for the module
to be activated in your catalog.

= Circulation =


== Patron Bills Interface Improvements ==

The Angular staff client Patron Bills interface has several display and
workflow improvements.

=== Patron Bills ===

 * The grid once again includes pagination and a rows-per-page selector.
 * The _Add Billing_ toolbar button is now labeled _Bill Patron_ to clarify
   that it creates a new billing transaction.
 * _Select All Bills_ and _Select All Refunds_ select matching bills across
   all pages and display the page containing the first selected bill.
 * Actions that operate on a single transaction, such as _Full Details_ and
   _Add Billing_, are disabled unless exactly one bill is selected.
 * Voiding billings for a large selection requires fewer server requests.
 * Submitting an empty payment amount no longer causes an interface error.
 * Flagged bill rows retain their visual status indicators when selected.
 * The Billing Location column now displays the circulation library for
   circulation bills.

=== Bill History ===

The Transactions tab restores the Last Billing Type, Last Billing Note,
Last Billing Time, Last Payment Type, and Last Payment Note columns.

The Payments tab restores the Last Billing Note, Total Owed, Total Paid,
and credit card Approval Code columns.

=== Bill Statements ===

Bill statements now distinguish billings, payments, adjustments, and voids.
Charges and payments are displayed with separate totals, and amounts that
reduce the balance are visually distinguished from charges.

The Owning Library in the Item Summary is now linked to the corresponding
library information page.


= Integrations =


== New RESTful API Endpoints ==

Endpoints have been added to Evergreen's OpenAPI implementation to
assist with search.

=== New Bibs Endpoint ===

The `bibsByISBN` endpoint allows retrieval of bibliographic records
via ISBN or other standard identifier using a `HTTP GET` request:

    GET https://<host>/openapi3/v0/bibs/by_isbn/<isbn>

The above returns different things depending on the content type
specified in the `Accept` header of the request:

[width="50%",cols="1,2",options="header"]
|====
|Content Type |Format
|application/json |Evergreen "bre" object
|application/xml |MARC of the record in MARCXML
|application/octet-stream |MARC of the record as binary USMARC
|====

=== Coded Value Maps Endpoints ===

Coded Value Map entries (useful for the Multiclass Search Endpoint,
see below) can be retrieved by database ID or all entries for a given
`ctype` can be retrieved at once:

    GET https://<host>/openapi3/v0/coded_value_map/<id>
    GET https://<host>/openapi3/v0/coded_value_maps/by_ctype/<ctype>

The former returns the single `ccvm` object and the latter returns a
list of `ccvm` objects.  The objects and list are formatted as JSON.

=== Mutliclass Search Endpoint ===

Evergreen's multiclass search capabilities, as used by the OPAC and
Staff Client Catalogs, can be accessed with the new
`search/multiclass` endpoint:

    GET https://<host>/openapi3/v0/search/multiclass?...

The new URL expects CGI query parameters that map to the underlying
`open-ils.search.biblio.multiclass` and
`open-ils.search.biblio.multiclass.query`x OpenSRF API routines.
Specifics of the CGI parameters accepted by the OpenAPI implementation
are documented in the table below:

[width="50%",options="header"]
|====
|Parameter |Value type |Repeatable |Default Value
|author |string |yes |none
|identifier |string |yes |none
|isbn |string |yes |none
|issn |string |yes |none
|keyword |string |yes |none
|series |string |yes |none
|subject |string |yes |none
|title |string |yes |none
|query |string |no |none
|org_unit |integer |no |none
|depth |integer |no |none
|limit |integer |no |10
|offset |integer |no |0
|sort |string |no |none
|sort_dir |string |no |ASC
|tag_circulated_records |boolean |no |false
|docache |boolean |no |true
|====

All of the parameters are optional, except that at least one of the
parameters from `author` through `query` MUST be provided.  The
`Default Value` column indicates the value used if the parameter is
not supplied.

Use of the `query` parameter triggers the use of
`open-ils.search.biblio.multiclass.query`.  It is expected to be
formatted just like the query string passed to that function.

The `sort` takes one of the options from the following list as the key:

  * author
  * title
  * pubdate
  * edit_date
  * create_date
  * rel
  * poprel

See `perldoc OpenILS::Search::Biblio` for documentation of
`open-ils.search.biblio.multiclass` and
`open-ils.search.biblio.multiclass.query`.
